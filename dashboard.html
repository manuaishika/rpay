The ₹12 Question

A Hinglish voice call costs ~₹12. Most failed payments aren’t worth ₹12. The agent’s real job is deciding who to call — and when to stop.

01

The wager

Five recovery policies run over the same 250-account book of failed payments. Every one passes through the same hard guardrail gate. The sequential ladder scores each still-allowed channel by expected net rupees and acts only when that number clears zero; the four fixed playbooks just run their script.

These are assumptions, not data. Every recovery probability lives in world.py and was invented to be plausible, not fitted to a real ledger. The pickup rate, the promise-to-pay conversion, the voice lift — all guessed. Section 04 sweeps them.
02

Scorecard

Net is recovered rupees minus spend. ₹/₹100 is what each policy spends to recover ₹100. Guardrail violations must be 0 — checked by an auditor that re-derives every rule from the emitted trail.

03

Where the edge comes from

Retrying the doomed has a price

A silent retry costs ₹0.50 and cannot fix an expired card or a revoked mandate. retry_only goes negative on exactly those reasons; the ladder scores them at zero and stops.

05

The hard gate

Not a prompt instruction — a gate. Every candidate action is checked before it can be played, and dropped from the choice set if it fails. A second, independent function re-derives all of it from the audit trail, so a gate bug surfaces as a counted violation instead of leaking.

07

The ₹12 call, rendered

For the calls the ladder actually chose, recovery/voice.py writes a reason-specific Hinglish script with sarvam-105b and renders it to a .wav with Sarvam’s Bulbul TTS. Scripts are model output, so they vary run to run; the economic model does not. No real number is ever dialled.
